We extend the results of Table 2 of the paper by Buhler, Golan, Pratt, and Wagon (Math. Comp. 90, 2021).

Background: m*(n) is the largest number m such that {1, …, n} can be split into two parts whose power sums are equal for every exponent k = 0, …, m − 1.

For example, if {1, 2, 3, 4} is partitioned into {1, 4} and {2, 3} then we have these power sums:

  k=0:   10 + 40   =   20 + 30   =   2
  k=1:   11 + 41   =   21 + 31   =   5
  k=2:   12 + 42   = 17   ≠   22 + 32   =   13.

Since the power sums are equal for k = 0 and k = 1 but not for k = 2, and since (exercise for the reader) no other bipartition of {1, 2, 3, 4} hits a bigger max k, we say that m*(4) = 2.

For {1, …, 8} it turns out there's a bipartition — {1, 4, 6, 7} and {2, 3, 5, 8} — that gets us up to k = 2, meaning m*(8) = 3:

  k=0:   10 + 40 + 60 + 70   =   20 + 30 + 50 + 80   =   4
  k=1:   11 + 41 + 61 + 71   =   21 + 31 + 51 + 81   =   18
  k=2:   12 + 42 + 62 + 72   =   22 + 32 + 52 + 82   =   102
  k=3:   13 + 43 + 63 + 73   =   624   ≠   23 + 33 + 53 + 83   =   672.

Fun fact, this property of having equal power sums for exponents from 0 up to some k is invariant under translating and scaling. In particular that means it doesn't matter if we use {1, …, n} or {0, …, n − 1} as the set to be partitioned. The m*(n) values are the same. You can in fact start with any set of n equally spaced integers.

From here on we use the convention that the n-element set to be partitioned is {0, 1, …, n − 1}.

Where the new results come from

Claude: "How the upper bounds are proven. Write a partition of 0, 1, …, n − 1 as signs f0, …, fn−1, +1 on one half and −1 on the other, and let f(x) = f0 + f1x + ⋯ + fn−1xn−1. Order m means that (x − 1)m divides f(x). For a modulus M, the residue sum Dr is the number of +1s minus the number of −1s at the positions i ≡ r (mod M). Reducing f(x) modulo xM − 1 leaves D0 + D1x + ⋯ + DM−1xM−1, which must still be a multiple of (x − 1)m modulo xM − 1. Each Dr also has the parity of its class's size and is at most that size in absolute value. The residue condition mod M rules out order m when an exhaustive search finds no residue sums that meet all of this."

Claude: "The norm bound for a prime p that does not divide n uses the same sums with M = p. Let ζ be a primitive pth root of unity. Then f(ζ) = D0 + D1ζ + ⋯ + Dp−1ζp−1 is not 0: if it were, the Dr would all be equal, hence all 0, as they sum to f(1) = 0; but since p does not divide n, some class has an odd size and so an odd Dr. It is a multiple of (ζ − 1)m, whose norm is pm, so the norm of f(ζ), a positive integer, is at least pm. By the inequality of arithmetic and geometric means, that norm is also at most (p ΣDr2 / (p − 1))(p−1)/2. With sr the size of class r and |Dr| ≤ sr, order m needs p2m (p − 1)p−1 ≤ (p Σsr2)p−1."

Claude: "mstar.py and pow2.py repeat the search behind every residue claim each time they run. Certificates that can be checked on their own, like proof512.wl for 512, are still to be done."

    Claude: "Whether order 12 is possible at 432 decides a(11) of OEIS A323395, the smallest n allowing order 12: 432 if so, 480 if not. The residue condition allows 1200 combinations of residue sums mod 3, 4, 5 and 7, and linear-programming certificates checked in exact integer arithmetic rule out all but two. A search can split each by the value of f′(−1) = Σ (−1)i−1 i fi, a linear function of the signs like the power sums. That value is an odd multiple of 8192, so never 0. The idea: mod 2, where every sign is 1, every sequence of length 432 is the same polynomial, with exactly 15 factors x + 1; the factors forced on f use all 15, so the rest of f is odd at −1."

    Claude: "In both combinations the residue sums mod 4 are all 0, so reducing f(x) modulo x4 − 1 leaves 0: x4 − 1 = (x − 1)(x + 1)(x2 + 1) divides f(x). So does (x − 1)12, by order 12, and as x + 1 and x2 + 1 share no root with x − 1, f = Fh with F = (x − 1)12(x + 1)(x2 + 1), where h has integer coefficients because F has leading coefficient 1. Then f = (x + 1)g with g = (x − 1)12(x2 + 1)h, and f′ = g + (x + 1)g′ gives f′(−1) = g(−1) = (−2)12 · 2 · h(−1) = 8192 h(−1)."

    Claude: "And h(−1) is odd. Mod 2, keeping only the parity of each coefficient, every sign is 1, so (x + 1)f = (x + 1)(1 + x + ⋯ + x431) = x432 + 1. As (a + b)2 = a2 + b2, x432 + 1 = (x27 + 1)16 = (x + 1)16S16, with S = 1 + x + ⋯ + x26, so f = (x + 1)15S16. And as x − 1 = x + 1 and x2 + 1 = (x + 1)2, F = (x + 1)12+1+2 too, so cancelling (x + 1)15 from Fh = f leaves h = S16. Then h(1) has the parity of S(1)16 = 2716: odd, and so does h(−1), which differs from h(1) by an even number."

    Claude: "As x + 1 divides f, f(−1) = 0: the numbers (−1)i−1fi are half +1 and half −1, so |f′(−1)| ≤ (216 + ⋯ + 431) − (0 + ⋯ + 215) = 2162 = 46,656. That leaves ±8192, ±24,576 and ±40,960, and further certificates rule out all but ±8192 in both combinations. Flipping every sign swaps the two combinations and negates f′(−1), so the search needs only f′(−1) = 8192, in both. Without the oddness of h(−1), it would also have to search f′(−1) = 0, where random root-to-leaf paths estimate a lower bound on the search tree's size about 12 times those for ±8192 combined."

    Claude: "At any length n = t·u, with t a power of 2 and u odd, the same steps give f = (x + 1)t−1St mod 2, where now S = 1 + x + ⋯ + xu−1 is u at 1, odd; as multiples of x + 1 are even at 1, f has exactly t − 1 factors x + 1 mod 2: a fixed budget. BGPW's Theorem 4.1 (Divisibility) and their Proposition 4.6, due to Berend and Golan, bound the order by it: m < t, and m < t − 1 if x + 1 divides f. The lemma: a divisor of f with leading coefficient 1 that uses the whole budget, as F does at 432, leaves a quotient odd at 1 and −1."

How Claude found its examples

The examples Claude found by searching, in the remarks above (p320, q336, p432, p560 and p800) and in early runs at 144 and 240, came from one method: a search for the shortest vectors of a lattice, run with the C++ library fplll.

Write a sequence as signs f0, …, fn−1 and let xi = 2i − n + 1, the positions centered on 0 and doubled. Order m means Σ fi xik = 0 for k = 0, …, m − 1: by the fun fact above, these positions give the same order as 0, …, n − 1, with smaller numbers. These are m linear equations in the signs. Claude looked only at symmetric sequences (fn−1−i = fi) for even m and antisymmetric ones (fn−1−i = −fi) for odd m, the paper's (−1)m convention. Since xn−1−i = −xi, that leaves h = n/2 unknown signs ai = fi (i < h) and ⌊m/2⌋ equations, those with k of the same parity as m; the others hold for every such sequence.

Put a = 2y − 1. The integer vectors y for which a solves the equations form a translate y0 + K of the lattice K of integer solutions of the equations themselves, whose dimension is d = h − ⌊m/2⌋. (If there is no such y, there is no such sequence.) So a ranges over the translate t + 2K, where t = 2y0 − 1. Every vector in it has odd entries, so its squared length is at least h, with equality exactly when every entry is ±1; any other vector in it has an entry of absolute value at least 3, so its squared length is at least h + 8. So the sequences sought are exactly the shortest vectors of t + 2K, and finding them is a closest-vector problem: find the vectors of the lattice 2K at distance √h from −t.

To search it, Claude reduced a basis b1, …, bd of 2K (LLL, then BKZ with block size 20) and enumerated. With b1*, …, bd* its Gram–Schmidt vectors, the squared length of t + c1b1 + ⋯ + cdbd is a sum of d terms, one along each bi*, and the term along bi* depends only on ci, …, cd. So the enumeration chooses cd, then cd−1, and so on, trying the integers at each step in order of the term they add (Schnorr–Euchner), and backs up as soon as the sum so far passes h. That tree holds every solution: run to the end, it is an exhaustive search over the sequences of that symmetry, and when it ends empty it proves there are none.

The tree grows about exponentially with d, so Claude pruned it: once j of the d coefficients are chosen, the sum so far must be at most a fraction pj of h, with the fractions rising to pd = 1 (extreme pruning: Gama, Nguyen and Regev, Eurocrypt 2010). A pruned run visits a small part of the tree and finds a given solution with some probability. Randomizing the basis and reducing it again gives another, nearly independent try. In the early runs fplll's Pruner chose the fractions. Every example found was then checked with exact integer power sums.

The searches, with d for the direct search and the times of the runs that found the examples (on one CPU in the claude.ai chat's sandbox, except 560 and 800):

  • 144, order 8, symmetric, d = 68: a new example in 2.4 seconds. The constraint solver CP-SAT, with exact residue-class constraints, didn't recover the paper's example in 250 seconds.
  • 240, order 10, symmetric, d = 115: one pruned enumeration of 57 seconds returned 8 different examples, and with retuned pruning 3 more came in 7 seconds.
  • 320, order 9, antisymmetric, d = 156: p320 in 0.7 seconds.
  • 336, order 9, antisymmetric, the piece q336 of 528. Claude kept the paper's p192, of order 9, and looked for an antisymmetric q of length 336 and order 9 whose 9th power sum is the negative of p192's. Then p192 ∨ q has order 10, because shifting q by 192 doesn't change its 9th power sum, its lower ones being 0. That is one more linear equation, whose right side is not 0, so d = 163, and t has a part outside the span of 2K, whose squared length comes off the h in the search. The first enumeration found q336 in 0.6 seconds.
  • 432, order 11, antisymmetric, d = 211: the chat's replies say only that p432 came from this lattice search, not its parameters or time.
  • 480, order 12, symmetric, d = 234: the chat's reply that reported p480 doesn't say how it was found.
  • 560, order 10, symmetric. A direct search would have d = 275, above fplll's limit of 256 for enumeration and far too slow, so Claude fixed more. The residue sums mod 27 (the Dr of the remarks above) were fixed to one pattern that the residue condition allows for order 10, the one that looked most likely, and the residue sums mod 5 and mod 7 to 0. Mod 27, the 280 pairs of positions i and 559 − i fall into 14 groups, by residue class together with its mirror image. In 7 groups, holding 135 of the pairs, every placement of the +1s with the count the pattern sets became a separate case. That left 145 free signs under 16 independent equations, so d = 129, and the same lattice for every case, with only t changing. The pruning fractions were a fixed shape, none below 0.3, picked by timing trial runs.   • 800, order 11, antisymmetric. A direct search would have d = 395, so Claude fixed more, as at 560. The residue sums mod 27 were fixed to the most likely pattern that the residue condition allows for order 11, refining the most likely one mod 9, the residue sums mod 5 to 0, and those mod 7 to their most likely pattern. lattice_search.wl is a plain Mathematica version of the direct search, without the matching or the fixed residue sums, to time against other search code. In place of fplll it uses LatticeReduce, which does LLL but not BKZ, and its own compiled enumeration, pruned by a simpler rule: the sum so far may be at most min(1, δ + j/d) times h, with δ the option "Pruning". δ = 1, the default, prunes nothing. δ = 0 is the linear pruning of Gama, Nguyen and Regev, too tight here: the solutions' sums run above j/d times h, most of all over the first coefficients chosen. An empty list of sequences proves there are none only when the result's "complete" is True, which takes an unpruned search that ran to its end; a search cut off by "MaxNodes" returns False, and its empty list shows only that none turned up in the part of the tree it searched. These calls have known results, in which each sequence's negation counts too:

  • latticeSearch[6, 2, 0]: complete, no sequences: the equations have no integer solution.
  • latticeSearch[32, 5, 0, "Want" -> Infinity]: complete, 2 sequences: Thue–Morse and its negation.
  • latticeSearch[48, 6, 1, "Want" -> Infinity]: complete, 2 sequences: the paper's p48 and its negation, as a brute-force check of all 224 symmetric sequences confirms.
  • latticeSearch[64, 6, 0, "Want" -> Infinity]: complete, 6 sequences: Boyd's 3 partitions.
  • latticeSearch[112, 7, -1, "Want" -> Infinity, "MaxNodes" -> 10^9]: complete, 2 sequences: the paper's p112 and its negation, after 285 million nodes, about 6 minutes on Danny Reeves's Mac. The tree's size depends on the random basis: with "Seed" -> 2 and 3 it took 224 and 966 million nodes.
  • latticeSearch[320, 11, -1, "Want" -> Infinity]: complete, no sequences, after a few nodes: the equations have integer solutions, but none with entries ±1.
  • latticeSearch[96, 7, -1]: 1 sequence.
  • latticeSearch[144, 8, 1, "Pruning" -> 0.1]: 1 sequence.
